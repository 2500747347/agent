# 03 生产级改造：从"能跑的 Demo"到"完整的 Agent 系统"

> 本文记录项目从"能跑"到"生产级完整"的八次改造（8 个 git 提交）。
> 每次改造都按**动机 → 实现 → 验证 → 提交**记录。

## 0. 改造动机：课程九层 × 项目差距矩阵

对照主流 Agent 能力框架逐层体检，初始项目能力完成度约 **27%**，
按优先级排出改造路线：

| 优先级 | 差距 | 对应改造 |
|---|---|---|
| **P0** | 会话记忆只有滑动窗口，被裁掉的旧消息永久丢失 | G1 历史向量检索 |
| **P1** | 上下文无预算控制，无限膨胀；无 token 估算 | G2 token 预算 |
| **P2** | TF 词面检索同义召回失败（"笔记本电脑"≠"电脑"） | G3 Embedding 语义检索 |
| **P1** | 模型可能传脏参数直接进真实函数 | G4 参数护栏 |
| **P1** | 危险工具无闸门，删数据无确认 | G5 工具分级 + 人工确认 |
| **P1** | 模型可能死循环、单轮工具可能卡死 | G6 循环终止机制 |
| **P1** | LLM 网络抖动/超窗/坏 JSON 直接崩溃 | G7 LLM 错误处理层 |
| **P2** | 黑盒运行，无法回答"Agent 干了什么、花了多少" | G8 可观测性 |

## G1 会话历史向量检索（`d34818a`）

**动机**：原实现滑动窗口只保留最近 N 轮，被裁掉的旧消息永久丢失——多轮对话中用户
早前提过的偏好、约定全部遗忘，且**存在 bug**：原 `_trim` 只删第一个 user 消息，
留下孤立的 assistant 消息破坏对话结构。

**实现**：
- 新增 SQLite 表 `conversation_history`，窗口裁剪时**整轮落库**（user+assistant 成对）
- 新建 `agent/history_memory.py`：`HistoryMemory.add_messages / retrieve`，
  定义 `Vectorizer` 协议（`vectorize(text, is_query) / similarity`）
- `memory.py._trim` 重构为整轮裁剪，修复孤立消息 bug

**验证**：新增 12 项测试；全量 24 项测试 + 45 条评测全绿。

---

## G2 token 预算（`f299b30`）

**动机**：上下文无上限，长会话必然超模型窗口；且原 `ensure_token_budget` 存在
**死循环 bug**（测试卡死 3 分钟）。

**实现**：
- `estimate_tokens` 精确化：中文≈1 字 1 token、ASCII≈4 字符 1 token
- `ensure_token_budget(budget)` 拆出 `_trim_one` 单轮裁剪（修复死循环，测试从 3 分钟→0.7s）
- Agent 总预算 8000 token；工具结果超 4000 字符截断

**验证**：28 项测试 + 45 条评测全绿。

---

## G3 Embedding 语义检索（`c1ba4ab`）

**动机**：TF 词面匹配召回不了同义表达。实测「我想找一份工作」vs「求职意向」：
TF 相似度 **0**，Embedding 相似度 **0.62**。

**实现**：
- 安装 sentence-transformers（清华源）+ torch CPU，经 hf-mirror 下载
  **bge-small-zh-v1.5**（~95MB）到 `models/`（首次因 xet 协议 401 失败，
  设 `HF_HUB_DISABLE_XET=1` 解决）
- 实现 `EmbeddingVectorizer`：本地路径加载、归一化点积=余弦、bge query 前缀
- `config.yaml` 加 `memory.vectorizer: tf | embedding` 开关，缺失自动回退 TF

**验证**：30 项测试 + 45 条评测全绿；`models/` 入 .gitignore。

---

## G4 参数护栏（`405d27b`）

**动机**：模型（尤其是弱模型）可能生成非法参数（越界、类型错），直接进真实函数
是安全隐患。

**实现**：
- `@tool` 新增可选 `params_model`（Pydantic BaseModel 子类，鸭子类型调用 `model_dump`，
  核心零依赖）
- `Tool.run` 执行前校验/强转，失败返回 `[参数校验失败] {exc}` 文本回填 LLM 自纠，
  **不执行真实函数**
- `dice_tool` 示范：`DiceParams(faces: int, ge=2, le=100)`

**验证**：+4 护栏测试（34 项）+ 45 条评测全绿。

---

## G5 工具分级 + 人工确认（`b4ad0df`）

**动机**：写操作（增删待办/笔记）与危险操作（删除）没有任何闸门。

**实现**：
- `@tool` 新增 `level`：`read`（默认）/ `write` / `danger`
- `Agent` 新增可选 `human_confirm(tool_name, args) -> bool` 回调；
  **danger 无确认器默认拒绝（fail-safe）**，拒绝/取消均回填模型
- 新增 `delete_todo` 作 danger 示范；`register_all` 自动扫描注册零装配

**验证**：+5 分级策略测试（39 项）+ 45 条评测全绿。

---

## G6 循环终止机制（`2496db2`）

**动机**：模型可能陷入"重复调同一工具"死循环，白白消耗 token 与时间；单轮工具
可能卡死（慢 API）。

**实现**：
- **重复调用检测**：连续相同 (工具, 规范化参数) ≥ 3 次判死循环提前终止；
  参数不同不算重复（防误伤）
- **单轮工具超时**：`tool_timeout`（默认 0 关闭），ThreadPoolExecutor +
  `shutdown(wait=False)` 超时不等待慢线程
- 测试中发现并修正：超时 FakeLLM 永远无视提示再调，修正测试断言 trace 超时结果

**验证**：+4 保险丝测试（43 项）+ 45 条评测全绿。

---

## G7 LLM 错误处理层（`71396b5`）

**动机**：真实 LLM 调用有三类高频故障——网络抖动/限流、上下文超窗、返回非法 JSON；
原来任何一类都直接抛异常崩溃，且**非法 JSON 被静默吞成 {}** 的隐蔽 bug。

**实现**：
- `llm.py` 本地异常体系：`LLMError`（致命）/ `LLMRetryableError`（可重试）/
  `ContextLengthExceeded`（超窗）
- `OpenAILLM` 指数退避重试（默认 3 次 1s→2s→4s）；超窗识别（BadRequestError
  含 context_length）
- 修复非法 JSON 静默吞 {} → 抛 LLMError
- `core.py` 4 类异常全部转可读文本兜底不崩溃；**超窗自动收缩窗口一半原轮重试一次**

**验证**：+8 测试（51 项）+ 45 条评测全绿。

## G8 可观测性（`204bdc0`）

**动机**：黑盒运行——回答"Agent 干了什么、调了几次工具、花了多少 token/时间"
没有任何依据。生产级与玩具的分界线。

**实现**：
- `agent/observability.py`：`AgentStats` dataclass + `JsonlLogger`（JSON Lines 写入）
- `core.py run()` 统计收口：统一 `_finish()` 组装 stats（steps / terminated_by /
  llm_calls / tool_calls / tool_errors / input / output / context_tokens / duration_ms）
- 结构化日志 `logs/agent.jsonl`：每步事件（llm_call / tool_call 含 ok / loop_detected）
  + summary 事件，含 session、step、工具名/参数/结果长度/是否成功
- 修复 steps 计数 bug（limit 场景多算 1）

**验证**：+7 测试（58 项）+ 45 条评测全绿；`logs/` 入 .gitignore。
